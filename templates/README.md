# 课程动作录入与交接

[打开 Google Sheet 基础模板](https://docs.google.com/spreadsheets/d/1dtBg9y6JfPOJqUyLxEPra2U1zyg1--yBwTmd7GunDms/edit)

主表“动作录入”从第6行开始填写，第5行是不会导入的示例。动作名称和体系必填。建议填写课程来源、目录和页码/时间点；肌肉、家族、别名等可以留空。不要为填满字段而猜分类。

当前动作模式与身体部位沿用原库。动作模式是：推、拉、蹲、髋铰链、负重行走、旋转、抗伸展、抗旋转、抗侧屈、爬行。“屈髋”“提起”不作为独立模式；原始动作名称仍照原文保留。肩胛骨单独列为身体部位。

## 增加选项

在“选项字典”对应列最后一个选项下方，逐行增加。主表下拉列使用跨表范围引用，预留1000个选项，499条新动作录入行及1行示例。超出预留行数时请扩展数据验证与表格范围。

身体部位、主要肌群、次要肌群使用原生多选下拉，可以逐项勾选。两栏肌群分别保存，均可留空。体系、功能、器械、别名与辅助标签可用逗号分隔；动作模式、区域和家族只填一个。旧版未区分主次的肌群不会自动归入主要肌群。

新增选项会即时出现在表格下拉中，**离线网站在导入交接包后更新**。网站不联网拉取Google Sheet，不会实时同步。

## 交给助手

1. 把准备导入的行设为“可导入”，其余行留为待整理或暂缓。
2. 在项目聊天中提供表格链接，注明本次课程或行范围。
3. 助手读取动作和选项字典，生成 `MovementLibraryIntakeV1` JSON 交接包。
4. 在动作库点击“导入课程动作 / 选项”，审阅新增条数和选项，再确认添加。

动作与字典在同一IndexedDB事务内写入。尚未被动作使用的新选项也会导入；之后导出整库备份时，字典也会保留。

新增导入保留已有笔记与附件。相同ID跳过，不自动覆盖；同名但不同ID保留为两条记录，不自动合并。填写“现有动作ID”不是更新指令；需要更新现有动作时另行明确说明。

## 自行离线转换

从Google Sheet的“文件 > 下载”选择 Microsoft Excel `.xlsx`，然后运行：

```sh
python3 templates/convert-intake.py '/path/to/课程摘录.xlsx'
```

同目录会生成 `.intake.json` 文件，在网站使用课程导入入口添加。标准库实现，无需安装第三方库。转换不会修改原表，只读取“可导入”的行和全部选项字典。

没有填写ID的新动作首次转换会获得新ID；重复导入**同一个JSON包**可按ID跳过。重新转换同一表格会生成不同ID，请不要把重新转换当作更新或去重。需要稳定对应时在表格回填现有ID，或让助手结合本地备份核对。

本地附件在网站动作详情中添加；表格只填写参考链接。课程目录与动作家族是独立字段，课程出处不自动改写原有动作的来源。

## 维护模板

`options.json` 是基础字典，来自现有动作库；`build-template.mjs` 创建基础工作簿，需要作者环境中的 `@oai/artifact-tool`。本地生成的 XLSX 不包含 Google 原生多选开关；复制现有 Google 模板可保留多选，从 XLSX 重建时需在数据验证中启用条状标签和允许多选。Google Sheet是用户日常录入入口，变动不自动写回Git仓库。个人课程摘录和附件也不会自动上传至公开仓库。

转换器回归：

```sh
python3 templates/test_convert_intake.py
```

## 表格图片

下载 XLSX 时，转换器会提取“动作录入”页中锚定到动作所在行的内嵌 PNG/JPEG/GIF/WebP 原图，随该动作写入本地附件。首张图片用于卡片封面，完整显示不裁切。请把图片放在对应动作行；跨行浮动图要先核对归属。外部 IMAGE 链接、无行锚点的浮动图尚不自动下载。

通常仍只导入“可导入”的行。仅在明确试用指定动作时，可用 `--rows 80,86` 指定行号；不会修改原表状态，也不应反复转换空ID动作来更新资料。图片随JSON备份保存；私人图片及试用包不提交公开仓库。
